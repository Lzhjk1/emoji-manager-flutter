# 重构方案：目录主分类 + 中央索引协调（混合方案）

> 状态：待实施
> 目标：一张图、一个文件，可映射到多个分类；文件仍按分类目录存放，资源管理器友好；索引只做"加法"，丢失可降级为现状行为。

## 一、核心原则

1. **文件物理位置不变**：图片仍存放在 `root/<分类目录>/xxx.png`，目录扫描结果是"主分类（home category）"。
2. **索引只存附加映射**：一张图要出现在其他分类，不复制文件，只在 `library.json` 记一条 link。
3. **降级安全**：索引丢失/损坏时系统退化为当前行为（纯目录扫描），零风险；索引从不改变目录扫描结果，只做加法。

## 二、library.json 设计

```jsonc
{
  "schemaVersion": 2,

  // 内容哈希注册表：hash → 实体文件当前路径（仅登记"应用经手过"的文件，
  // 不要求全库哈希；配合 size 预筛实现低成本去重与自愈）
  "hashes": {
    "a3f9c2e8d1...": "QQ/angry.png"
  },

  // 附加分类链接：仅收录"被加入过其他分类"的图片
  "links": [
    {
      "path": "QQ/angry.png",        // 相对 root 的路径（link 主键）
      "hash": "a3f9c2e8d1...",       // 内容 SHA-256，自愈依据
      "size": 24576,                 // 字节数，自愈候选预筛依据
      "addedAt": 1725000000000,
      "categories": ["喵星人", "斗图"]  // 额外分类（不含 home 分类）
    }
  ]
}
```

- 原子写：先写 `library.json.tmp` 再 rename。
- 启动加载时对账：指向不存在文件的 link 进入自愈流程（见第五节）。

## 三、自动去重方案

**思路：size 预筛 + 哈希精验**，避免全库哈希的高昂成本。

### 导入流程（`_importImageToCategory` 改造）

1. 读取源文件 `size`，流式计算 SHA-256（`crypto` 包，需新增依赖；大文件用 chunked 读取，几 MB 毫秒级，必要时放 isolate）。
2. **快速判重**：在当前扫描结果中查找 `size` 完全相同的已有文件（扫描时顺带记录每个文件的 size，成本为零）。
   - 无同 size 文件 → 内容必然不同（SHA-256 碰撞实际不可能）→ 正常复制。
3. 有同 size 候选（通常 0~1 个）→ 对候选计算哈希（或查 `hashes` 注册表直接命中）：
   - 哈希相同 → **不复制**，为该已有文件写一条 link（加入当前分类），返回原文件路径的 item。
   - 哈希不同 → 正常复制，并把新文件的 hash/size 登记（link 创建时登记；未建 link 的普通导入也登记 hash，扩大注册表覆盖）。
4. UI 反馈：汇总提示"导入 N 张，跳过重复 M 张（已添加到当前分类）"。

### 已有重复文件的清理（P2，不在首版）

- 扫描时顺带按 size 分组统计重复嫌疑项，形成报告。
- 提供"合并重复"操作（保留一个实体，其余转为 link），**不自动执行**，避免误删用户文件。

## 四、自愈方案（改名/移动后 link 丢失）

### 触发时机

每次 `scanWithMetadata` 对账时发现 link.path 指向的文件不存在。

### 自愈算法

1. **候选生成**（利用 link 记录的 size/hash）：
   - 候选 A：全树扫描结果中 `size` 相同的文件（最稳线索，改名不改内容时 size 不变）。
   - 候选 B：文件名相同的文件（覆盖"内容被替换但名字沿用"的边角情况，需哈希验证兜底）。
   - 候选优先级：先 A 后 B，合并去重。
2. **哈希验证**：逐个候选流式计算哈希（已算过的用注册表/本次扫描缓存），等于 `link.hash` 即命中。通常候选极少，成本可忽略。
3. **多候选命中**（库内存在重复文件）：
   - 选择策略：优先同目录名 → 其次文件名相同 → 最后路径编辑距离最小。
   - 其余候选记入日志（WARN 级）。
4. **自愈成功**：更新 `link.path` 与 `hashes` 注册表 → 保存索引 → 汇总到悬浮窗提示。
5. **自愈失败**：link 标记为 `missing`（保留记录，不自动删除），UI 中对应条目置灰并显示"文件已丢失"角标，提供"移除失效链接"操作；记日志。

### 悬浮窗提示

- 应用内 overlay（Stack 顶层浮动卡片，非系统级窗口）：启动/重扫后若有自愈或丢失事件，展示：
  - "检测到 2 个失效链接：已自动恢复 1 个（QQ/angry.png → QQ/angry_new.png），1 个无法恢复"
- 自动消失（约 8s），点击可打开 logs 目录。
- 无事件时不打扰。

### 成本控制

- 自愈只对**候选文件**算哈希，不做全库哈希扫描。
- 哈希结果在单次扫描会话内缓存，重复验证不重算。

## 五、日志系统

### 位置与生命周期

- 目录：`<root>/logs/`
- 每次启动创建一份：`app_20260902_153012.log`（启动时间戳命名）。
- 轮转：保留最近 30 份，启动时静默清理更早的。

### 格式

```
2026-09-02 15:30:12.345 [INFO] 启动 emoji_manager v1.0.0，根目录: E:\emojis
2026-09-02 15:30:13.102 [INFO] 扫描完成: 12 个分类, 1834 张图, 耗时 742ms
2026-09-02 15:30:13.210 [WARN] 链接失效: "QQ/angry.png" → 尝试自愈
2026-09-02 15:30:13.530 [INFO] 自愈成功: "QQ/angry.png" → "QQ/angry_new.png" (hash 匹配)
2026-09-02 15:30:13.540 [WARN] 无法恢复的链接: "表情包/old.gif" (无可匹配候选)
2026-09-02 15:30:20.001 [INFO] 导入 3 张, 去重跳过 1 张 (hash=a3f9c2e8…)
```

- 级别：INFO / WARN / ERROR（ERROR 附堆栈）。
- 记录事件：启动与版本、根目录、扫描摘要（分类数/图数/耗时）、link 丢失与自愈结果、去重命中、导入结果、异常。

### 实现

- 新增 `EmojiLogService`（单例）：`info/warn/error` 接口，内存缓冲 + 定时批量落盘（减少 IO）；同时 `debugPrint` 便于开发期观察。
- 日志写入失败静默忽略（不影响主流程）。

## 六、各模块影响

| 模块 | 改动 |
|---|---|
| `scanWithMetadata` | 扫描后应用 links（item `copyWith(category: 附加分类)`）；收集 size；对账触发自愈 |
| `EmojiItem` | 加 `homeCategory` + `isLink` 标记、`fileSize` 字段 |
| 缩略图 / 备注 / 最近使用 / 剪贴板 | **零改动**（按实体路径走，多分类共享同一份备注与缩略图） |
| 排序 | 附加分类中链接项按 `addedAt` 排在原生项之后；手动排序仅作用于 home 分类（order.json 不动），后续如需再扩展 per-category order |
| 删除 | 链接分类里删除 = 只移除 link；home 分类里删除 = 删文件并清理指向它的所有 link + 注册表条目 |
| 拖拽导入 | 接入第三节去重逻辑 |
| 新建分类 | 直接建目录（保持"每分类必有目录"，索引里无 virtual category 概念） |
| `emoji_cache_service` | 缓存带 schemaVersion 失效重建一次（itemsByCategory 会多出链接项） |

## 七、已知取舍

1. **link 以路径为主键**：改名/移动导致 link 失效，但第五节自愈可自动找回（依据 hash+size）；找不回时置灰提示，不丢 home 分类。
2. **home 分类不可移除**：文件在哪个目录就属于哪个分类；"从主分类移出"等价于移动文件（可后续提供"移动到分类"操作 = 移动文件 + 更新 links）。
3. **去重依赖注册表/size 预筛**：外部手工放进目录且从未经应用导入的文件，首次与后续导入判重时通过 size+哈希兜底识别，覆盖完整。

## 八、实施步骤

1. `EmojiLogService` 日志系统（独立、无风险，先行落地）。
2. `EmojiLibraryIndex` service：library.json 读写（原子写）、hashes/links 管理。
3. 扫描集成：应用 links、记录 fileSize、对账 + 自愈、悬浮窗提示。
4. 导入去重：`crypto` 依赖 + size 预筛 + 哈希精验 + 汇总提示。
5. Controller / UI：添加到分类（多选对话框）、从分类移除、链接角标、失效链接置灰与移除入口、缓存 schemaVersion。
6. （P2）重复文件报告与合并、per-category 排序。

## 九、升级路径

若日后想转向"内容寻址全量重构"（images/<hash>.ext 扁平存储），`hashes` 注册表 + `links` 可直接映射为新索引的 images/memberships，已积累的数据不浪费。
